# Audit 0059 — the `previous_response_id` conversation copy

## Finding: confirmed, bounded

`ResponseStore.Entry.conversation` is `inputItems + outputItems`, so every
continuation read allocates a fresh array of the whole flattened history. This
is an O(history) copy; audit 0018's byte budget is what bounds it, because an
entry's weight counts both item arrays. The question here is whether to replace
it with a lazy view or to document the measured cost.

Decision: **keep the array and document it.** `ResponsesAPIMapper.chatRequest`
consumes `[Item]` and the response's exact input is an `Array`; a lazy
`RandomAccessCollection` would either change that API or be materialised at the
mapper anyway, and the budget already caps the allocation. No behaviour changed.

## Measurement and test

`sources/TinyTitanServer/Core/ResponsesAPIStore.swift` now documents the copy and
points at the test.

`tests/TinyTitanServer/ResponseStoreTests.conversationCopyIsBoundedByTheEntryBudget`:

- builds an entry with 200 input + 200 output items of ~400 characters each and a
  100-byte response JSON;
- measures the entry's logical retained bytes (`entryBytes`) and the bytes of
  `entry.conversation` (`copyBytes`);
- asserts `entry.conversation.count == 400`;
- asserts `copyBytes == entryBytes - 100` — the copy is exactly the two item
  arrays, no hidden growth;
- asserts `copyBytes <= entryBytes <= 16 MiB` (the default per-entry budget);
- a store with `maximumEntryBytes == entryBytes` stores the chain and accounts
  exactly `entryBytes`; one byte less is `.rejectedEntryTooLarge` and leaves the
  store empty.

`swift test --no-parallel --filter ResponseStoreTests` -> 16 tests passed.

## Residual

- The measurement is logical JSON bytes, not RSS; the transient array has
  allocator overhead beyond the pinned number, as the store's own doc says.
- Each continuation still pays the copy once; that is O(history) CPU, bounded by
  the 16 MiB entry budget. A future lazy view would need an API decision, not a
  micro-optimisation hidden in the store.
