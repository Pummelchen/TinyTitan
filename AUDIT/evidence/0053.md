# AUD-0053 — checked integer conversion in the Inkling 2 architecture readers

Commit: `audit(0053): …` (see `git log --grep 'audit(0053)'`)

Baseline: detached `95e925ce` (after AUD-0044).

## Defect proved before the fix

`Inkling2GGUFArch.archInfo` turned untrusted metadata into `Int` with plain
`Int(Double)`:

```swift
func int(_ key: String) throws -> Int { Int(try number(key)) }
...
return Int(first)                          // head_count list
...
let passes = Int(header.number("inkling2.num_loops") ?? 1)
```

`Int(_: Double)` traps for NaN, ±infinity and any value outside `Int`. The
architecture reader runs **before** the planner arithmetic fixed in AUD-0039, so
a GGUF whose `inkling2.rope.dimension_count` is a real NaN crashed `plan` with
SIGTRAP. `Inkling2CheckpointArch.int` had the same `Int(value)` after only
`rounded()`/`>= 0` checks; `1e300` passes both and traps.

### RED (fixture test run against the unchanged sources)

`tests/TinyTitanRepack/Core/Format/Inkling2GGUFArchTests.swift` builds a

## Fix

- `sources/TinyTitanRepack/Core/Format/Inkling2GGUFArch.swift`:
  `integer(_:field:)` uses `Int(exactly:)` and throws
  `RepackError.configurationInvalid` naming the key (NaN, ±inf, fractional and
  out-of-range all fail). `int`, `firstOf`, and the loop count all go through
  it. `slidingLayers` now takes the already-checked `passes` instead of
  re-reading and re-converting `inkling2.num_loops`.
- `sources/TinyTitanRepack/Core/Format/Inkling2CheckpointArch.swift`: the
  sibling `Int(value)` is now `Int(exactly:)`, keeping its existing
  `rounded()`/`>= 0` checks. `1e300` is rejected with the same typed error.
- `tests/TinyTitanRepack/Core/Support/Inkling2GGUFFixture.swift`: a
  metadata-only GGUF v3 builder and a complete valid Inkling 2 fixture (two
  stored layers, two passes, two experts, head dimension 8), reused by
  AUD-0054/0055.

Valid documents are unchanged: the fixture's complete metadata reads the same
architecture, and the gated real-model tests still compile/skip.

## Residual risk

- `Int(exactly:)` accepts any exactly representable integer the Double holds;
  a GGUF metadata count above 2^53 that is not a power of two is not exactly
  representable and is refused. Real GGUF counts are far below 2^53; the
  alternative (a rounded count) would be worse.
- Non-integer scalar metadata (epsilon, scales) is still read as `Double`; no
  conversion, so no trap. AUD-0055 covers the one zero geometry that can make a
  derived value non-finite.

## New findings

1. The checkpoint sibling `Int(value)` in `Inkling2CheckpointArch` is fixed in
   this commit; it is the same defect class.
2. `GGUFHeaderV3.number` returns `Double` for integer metadata, so a `uint64`
   count above 2^53 loses precision *before* `Int(exactly:)` sees it (for
   example, `2^53 + 1` arrives as `2^53` and is accepted as an exact value).
   This is not a trap and no supported model has a count anywhere near 2^53,
   but an exact-integer accessor on `GGUFHeaderV3.Value` would be the right
   follow-up if the architecture reader ever consumes `uint64` counts at that
   scale. Recorded, not changed here.
