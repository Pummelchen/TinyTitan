# AUD-0041 — `maximumEnd` must not trap on a wrapping frame

Commit: `audit(0041): …` (see `git log --grep 'audit(0041)'`)

Baseline: detached `cbdb6da0` (after AUD-0040).

## Defect proved before the fix

`ExpertBlobIndex.maximumEnd([[Blob]])` computed

```swift
end = max(end, frame.offset + UInt64(frame.length))
```

`+` on `UInt64` traps at `UInt64.max`. The doc said entries come from `decode`,
which already refuses a wrapping end — but the streamer also holds raw frame
lists produced by `compressExpert`, and a direct package caller can pass any
blob. The failing-before test used `offset = UInt64.max - 4, length = 16`:

```
swift test --no-parallel --filter maximumEndSaturatesOnWrap
Test "A wrapping frame end saturates instead of trapping" started.
error: … exited with unexpected signal code 5     # SIGTRAP at offset + length
```

## Fix

`ExpertBlobIndex.maximumEnd` now uses `addingReportingOverflow` and returns the
explicitly documented non-valid saturation `UInt64.max` when a frame wraps:

```swift
let (frameEnd, overflow) = frame.offset.addingReportingOverflow(UInt64(frame.length))
guard !overflow else { return UInt64.max }
```

`UInt64.max` is not a usable layer size, so both consumers refuse it through
the checks they already have:

- `Model+LayerStreamers.streamSize` guards `end > 0` and returns it; the
  streamer's `streamOffset + streamSize` check keeps it representable, and
  `fileSize < required` then raises `sizeMismatch` (a 16 EiB file cannot exist
  on this platform).
- `PackedExpertLayoutVerification` guards `end > 0, end <= actualSize` and
  raises the existing `RepackError.configurationInvalid`.

No signature changed; the valid path is byte-identical (the highest end of a
non-wrapping list is unchanged).

## Tests added

`tests/TinyTitan/Infrastructure/Streaming/ExpertBlobIndexTests.swift`:

- a wrapping `(UInt64.max - 4, 16)` blob saturates through both overloads;
- a valid frame beside the wrapping one still saturates (the unrepresentable
  result is not masked by `max` with a smaller end);
- the existing `maximumEndIsTheHighestFrame` still pins 250 for valid frames.

`swift test --no-parallel --filter ExpertBlobIndex`: **18 tests / 2 suites**,
pass.

## Residual risk

- Saturation is a non-valid value by contract: a caller that only checks
  `end != 0` and uses it as an allocation size would ask for 16 EiB and fail
  allocation instead of getting a typed error. Both current consumers compare it
  to a file size first. A throwing signature would be stronger but would change
  four call sites and the three duplicated streamers for a case `decode` already
  refuses; recorded here rather than done.
- No layer written by this tree can produce a wrapping frame (`compressExpert`
  writes offsets from real bytes and lengths as `UInt32`), so this is a defence
  for corrupt/hand-built input, not a change for valid installs.
