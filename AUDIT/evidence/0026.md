# AUD-0026 — compaction headroom is a safe whole number of tokens

Commit: (see `git log --grep 'audit(0026)'`)

## Root cause

`plugins/dsh-tinytitan/src/config.js`'s `resolveCompactionHeadroom` did
`const tokens = Number(value)` then `Number.isInteger(tokens) && tokens >= 0`.
That accepted:

- integer-valued numbers past `Number.MAX_SAFE_INTEGER`
  (`9007199254740992` and `1e21`), where the subtraction the engine performs on
  the value silently loses precision;
- coercions: `true` → 1, `false` and `[]` and `[8192]` and `""` and `" "` → 0,
  `"8192 "`/`"0x2000"`/`"1e4"` → 8192/8192/10000.

Only non-integers, negatives, `NaN` and infinities were refused. The sibling
token-count resolvers (`resolveRouteTokenCount`, `resolveAutoGoalRounds`, …)
already use `Number.isSafeInteger`.

## Fix

`resolveCompactionHeadroom` now accepts exactly two shapes and refuses everything
else instead of coercing:

- a `number` that is `Number.isSafeInteger(value) && value >= 0`;
- a `string` matching `^(?:0|[1-9][0-9]*)$` whose value is a safe integer.

`undefined`/`null` still mean `null` ("name no headroom; the harness's 65536
stands"), `0` is still a real value written into the preset. The error message and
field name are unchanged (`compactionHeadroomTokens must be a whole number of
tokens, got …`), and it carries no secret — only the offending config value.

The accepted range and type are documented in the function's JSDoc and in the
README's config table row: `0` to `2^53 - 1`, as a number or plain decimal text.

## Residual risk

- `2^53 - 1` is accepted even though such a headroom makes the engine's message
  budget negative on every real window; that is the engine's documented
  "never compacts" configuration, not a value this plugin can judge without
  knowing the routed window at config time.
- Sibling findings, deliberately not changed here (out of task scope):
  `resolveDebounce` (`config.js`, `Number.isFinite` after `Number(value)`) still
  coerces `true`/`""`; `resolveHandoffWindowRatio` does the same and would accept
  `true` as 1. Both are recorded in the task report.
