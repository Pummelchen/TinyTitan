# Audit 0020 — parse the media type exactly

## Finding

Confirmed by source and by test. `HTTPServerHandler+Routes.swift` admitted a JSON
body route when

    head.headers.first(name: "content-type")?.lowercased()
        .hasPrefix("application/json") == true

`application/jsonx`, `application/json-foo`, `application/vnd.api+json`, a
dangling `application/json;` and a value-less parameter all passed that test.
`unload` used the same prefix test behind an absent-header allowance.

Reproduced before the fix with the extended tests:

    swift test --no-parallel --filter HTTPServerTests
    -> Test run with 33 tests in 1 suite failed after 14.754 seconds with 99 issues.

The failures are the `application/jsonx` / `+json` / malformed-parameter cases
in `everyJsonRouteRefusesANonJsonContentType` and
`unloadRefusesABrowserFormPost`, plus `duplicateContentTypeIsRefused` (two
`Content-Type` fields were admitted; the old code read the first).

## Change

- `sources/TinyTitanServer/Core/HTTPMediaType.swift` (new): an RFC 7231
  media-type parser. Type, subtype and parameter names are case-insensitive;
  parameters may be tokens or quoted-strings; duplicate parameter names and
  malformed parameter syntax are invalid. A structured `+json` suffix is
  deliberately **not** `application/json` — recognising it by suffix would
  repeat the prefix mistake. `HTTPHeaders.requestContentType()` classifies
  absent / exact / invalid / duplicate using every raw header value.
- `HTTPServerHandler+Routes.swift`: `jsonBody` requires exactly one valid
  `application/json`; `notAForm` keeps the absent-header allowance only for the
  bodyless unload route. Both now share the same parse.

No new dependency, no public API change.

## Tests

- `tests/TinyTitanServer/HTTPMediaTypeTests.swift` (new): grammar boundaries,
  casing, parameters, quoted pairs, `+json`, malformed values, duplicate
  parameters, and header classification.
- `tests/TinyTitanServer/HTTPServerTests.swift`:
  `everyJsonRouteRefusesANonJsonContentType` extended to nine rejected media
  types across all five JSON routes, asserting 415, the surface envelope and
  zero backend calls; `unloadRefusesABrowserFormPost` extended with `jsonx`,
  `+json`, empty parameter and a value-less parameter;
  `unloadAcceptsExactJsonAndAbsentMediaType`, `duplicateContentTypeIsRefused`
  (raw socket, two header fields) and
  `exactJsonMediaTypeCasingAndParametersAreAccepted` added.

Passing after:

    -> Test run with 41 tests in 2 suites passed after 12.829 seconds.

## Residual risk

The parser accepts optional whitespace around `=` (more lenient than the
grammar, never less). The media type is still not a trust boundary for a
browser: `application/json` forces a CORS preflight, which the server does not
answer, but Host/Origin policy is audit task 0019.
