# AUD-0033 — reject coerced types for the debounce and the handoff window ratio

Commit: (see `git log --grep 'audit(0033)'`)

## Root cause

`plugins/dsh-tinytitan/src/config.js` validated two more operator numbers with
`Number.isFinite(Number(value))`, the pattern AUD-0026 replaced for
`compactionHeadroomTokens`:

- `resolveDebounce` — `Number(value ?? 2000)`; `true` became 1 ms, `false`/`""`/
  `[]` became 0, `[2000]` became 2000, and `"2e3"`/`"0x7d0"` became 2000, while
  an integer-valued number past `Number.MAX_SAFE_INTEGER` was accepted outright.
- `resolveHandoffWindowRatio` — `Number(value)`; `true` became the ratio 1 (a real
  change: "fraction of the window" was never 1), `[0.6]` became 0.6, and `""`
  silently meant "use the default".

Both values are arithmetic (a timer delay and a fraction multiplied into a token
budget), so a coerced type is a configuration the operator never declared.

## Fix

The same explicit type rules as `resolveCompactionHeadroom` (AUD-0026), with the
shared decimal grammars moved above their first user:

- `DECIMAL_INTEGER = /^(?:0|[1-9][0-9]*)$/` — plain whole-number text, no sign,
  no exponent, no leading zero, no whitespace;
- `DECIMAL_FRACTION = /^(?:0|1)(?:\.[0-9]+)?$/` — plain decimal text for a ratio.
- `resolveDebounce`: `undefined`/`null` → `2000`; otherwise a `number` that is
  `Number.isSafeInteger(value) && value >= 0`, or a `DECIMAL_INTEGER` string whose
  value is a safe integer. Everything else is refused with the existing
  `watchDebounceMs must be milliseconds` message.
- `resolveHandoffWindowRatio`: `undefined`/`null` →
  `DEFAULT_HANDOFF_WINDOW_RATIO` (0.6); otherwise a `number` that is finite and in
  `(0, 1]`, or a `DECIMAL_FRACTION` string whose value is in `(0, 1]`. Everything
  else is refused with the existing `above 0 and at most 1` message. The range is
  unchanged — only the type gate is new — so `0.25`, `1` and `"0.6"` still work.

One deliberate narrowing, called out because it changes a sentinel: the ratio no
longer treats `""` as "unset". AUD-0033 asked for empty strings to be rejected,
and an empty quoted value is a profile typo, not a way to say "use the default"
(`null`/absent still is). No test or documented example used `""`.

## Residual risk

- `DECIMAL_FRACTION` rejects `.6` and `1e-1` as strings while a YAML number `.6`
  is fine (YAML parses it as the number 0.6). A profile that quoted a
  non-canonical spelling is refused rather than guessed at, which is the direction
  AUD-0033 asked for.
- `2^53 - 1` milliseconds is accepted for the debounce even though it is ~285,000
  years; the field is a timer delay and the bound is the arithmetic's, not a
  usefulness judgement.
- Siblings measured and **not** changed (out of task scope; reported):
  `plugins/dsh-tinytitan/src/config.js:216` (`resolveRouteTokenCount`, used by
  `context`/`maxTokens`) and `:345` (the `port` block in `resolveConfig`) still go
  through `Number(value)` + `Number.isInteger`/`Number.isSafeInteger`, and were
  measured to accept coerced types: `port: true` → 1, `port: [8096]` → 8096,
  `context: true` → 1, `context: [65536]` → 65536. The other handoff resolvers and
  the goal/autonomy round caps already use `Number.isSafeInteger` without
  coercion of non-strings (they still accept `"8192"` by design).
