# Audit 0058 — duplicate anthropic-version

## Finding: confirmed

`route` detected the Messages surface with
`head.headers.first(name: "anthropic-version") != nil`. A request carrying two
`anthropic-version` fields therefore selected a surface by wire order.
Reproduced before the fix with a raw-socket `/v1/messages` request: 200, backend
invoked (the new test recorded four failing expectations: status, surface
envelope, the header name, and zero generations).

## Change

`sources/TinyTitanServer/Core/HTTPServerHandler+Routes.swift`:

- Reads every `anthropic-version` value once. Two or more is refused before
  routing with 400; the Anthropic envelope is used because the request claimed
  that surface (`invalid_request_error`, message naming `anthropic-version`;
  the Anthropic envelope has no `code` field by design).
- The refusal goes through `writeAdmissionRefusal`, so a HEAD request is
  bodyless, as with the Host/Origin and workspace refusals.
- A single header still selects the Messages surface exactly as before.

## Tests

`tests/TinyTitanServer/HTTPServerTests.swift`:

- `duplicateAnthropicVersionIsRefused` (raw socket): two values -> 400,
  `invalid_request_error`, message names `anthropic-version`, zero generations.
- `aSingleAnthropicVersionSelectsTheMessagesSurface` (raw socket): one header ->
  200, `request-id` present, one generation.

Focused run: 17 tests in 2 suites passed (together with the workspace and trust
suites).

## Residual

A duplicated `anthropic-version` on an unknown path is refused the same way;
the surface choice for a single header is unchanged. No legitimate documented
client sends two values.
