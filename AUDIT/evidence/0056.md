# AUD-0056 — checked resident-index and cursor arithmetic in the checkpoint planner

Commit: `audit(0056): …` (see `git log --grep 'audit(0056)'`)

Baseline: detached `828ea48f` (after AUD-0055).

## Defect proved statically

`Inkling2CheckpointPlanner` copied the GGUF planner's old unchecked shapes:

```swift
// planResident
let rawIndex = UInt64(
    SSDAIBinary.indexHeaderBytes + tensors.count * SSDAIBinary.indexEntryBytes
        + stringTable.count)
...
cursor += tensor.sizeBytes

// planLayer.add
guard dtypeName == sourceDType, tensor.sizeBytes == bytes * UInt64(experts)
...
cursor += bytes

// planLayer
encoding == .nvfp4 ? packed * 2 : packed
UInt64(experts)                       // traps for a negative expert count
```

Every factor comes from a safetensors header or the architecture:

- `tensors.count` / the string table are bounded by the index cap today, but
  the `Int` product and sum are unchecked;
- `tensor.sizeBytes` and `bytes * experts` are declared sizes, so the cursor
  `+=` can overflow `UInt64`;
- `experts` came from `arch.numExperts` without a positivity guard, so
  `UInt64(experts)` traps for a negative value and `0..<numLayers` traps for a
  negative layer count.

**RED note.** A behavioural fixture would need an `Int`-sized resident index
(10^17 tensors) or a >16 EiB resident tensor, and `plan` derives both from real
file headers/sizes; nothing smaller reaches the overflow. As with AUD-0040/0043
the failing-before proof is static and the boundary is pinned on the extracted
helpers.

## Fix

`sources/TinyTitanRepack/Core/Planning/Inkling2CheckpointPlanner.swift`

- `plan` guards `arch.numLayers > 0` and `arch.numExperts > 0` before
  `0..<numLayers` / `UInt64(experts)`.
- `checkedAdd` / `checkedProduct` (UInt64) throw
  `RepackError.configurationInvalid` on overflow; both cursor updates use them.
- `residentIndexSize(tensorCount:stringBytes:)` computes
  `header + count * entryBytes + stringBytes` with the shared checked `Int`
  helpers from AUD-0054 (`Inkling2Arch.checkedMultiply/checkedAdd`).
  `planResident` calls it before sizing the index and rejects a negative
  result (defence in depth; non-negative inputs cannot produce one).
- `planLayer.add` computes `bytes * experts` with `checkedProduct` before
  comparing it with the source size, and maps `packed * 2` through
  `checkedProduct`.
- The cursor update in `planResident` and `planLayer` is a checked add.

For valid values every helper returns exactly the old expression, so the plan
and the written bytes are unchanged. The gated real-checkpoint tests compile and
skip; the non-gated config/name tests pass.

## Residual risk

- The resident index/tensor counts that would overflow are not constructible
  from a real checkpoint (the loader caps the index and file sizes), so the
  checks are guards rather than a new rejection for any valid plan.
- `encoding.payloadBytes` / `scaleBytes` were already checked
  (`ssdaiCheckedMultiply`), and the layer cursor is now checked too; the
  remaining `shape + [0…]` padding uses a rank already validated `<= 4`.
