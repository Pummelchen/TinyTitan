# Task 0038 — manifest dependency declarations versus actual imports

Status: DONE.

## What was wrong

The source-derived import graph (`AUDIT/contracts.md`) showed:

- `TinyTitanServer` imports `TinyTitanCore`, `TinyTitanLegacyEngine`,
  `TinyTitanLib` and `TinyTitanMemory` in `Command/main.swift` but declared only
  `TinyTitanServerCore`, `TinyTitanVariants`, `TinyTitanCPUEngine` and
  `TinyTitanPluginAPI`. SwiftPM exposes a dependency's transitive modules on the
  search path, so it built, but the manifest under-declared the coupling.
- The six `Qwen35Dense{2B,4B,9B}{4Bit,8Bit}` targets and `TinyTitanLib` declared
  `TinyTitanFormat` with no direct `import TinyTitanFormat` in the target.

## Fix

`Package.swift` only:

- `TinyTitanServer` dependencies now include `TinyTitanCore`,
  `TinyTitanLegacyEngine`, `TinyTitanLib` and `TinyTitanMemory`.
- The six dense targets drop the unused `TinyTitanFormat`.
- `TinyTitanLib` drops the unused `TinyTitanFormat`.

`TinyTitanRepackCore` keeps its `TinyTitanFormat` dependency: it does import the
module (the first pass over-matched and was corrected before building).

## Verification

- `swift package dump-package`: exit 0; target names/dependencies consistent.
- `swift build -c release`: **exit 0**, 596.13 s, no warnings.
- `swift build --build-tests`: **exit 0**, **0** `warning:` lines.
- No product source changed; the runtime and all tests see the same code.

The source-derived graph should now match the manifest for these targets; a
future regeneration of `AUDIT/contracts.md` is the check for the reverse drift.
