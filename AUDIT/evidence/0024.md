# AUD-0024 — atomic settings replacement with concurrent-edit detection

Commit: (see `git log --grep 'audit(0024)'`)

## Root cause

`plugins/dsh-tinytitan/src/generate.js`'s `replaceSettingsFile` read the settings
file, optionally `copyFileSync`d it to `.bak-<stamp>`, then called
`writeFileSync(settingsPath, after)` — a truncate-and-write in place. An ENOSPC,
a crash or a failing sync there left a partial profile; a backup is a copy, not a
way back. Any editor that saved between the read and the write had its change
overwritten with a block computed from the stale text. Two refreshes in the same
stamp second overwrote each other's backup.

## Fix (`src/generate.js`)

- One replacement path shared by the route block writer and the default-model
  repair:
  1. resolve the settings path (`realpathSync`), so a symlinked profile stays a
     symlink and its target is replaced;
  2. create an exclusive same-directory temp file
     `.<name>.tmp-<pid>-<stamp>` (`openSync(..., "wx", 0o600)`, up to 16 names);
  3. write, `fchmod` the original mode, `fsync`, `close` — the bytes are durable
     and complete before the target is touched;
  4. re-read the target and compare with the exact `before` text the new text was
     computed from; a difference throws `ESETTINGSCHANGED` /
     `changed while the route was being written; nothing was replaced` and leaves
     the file alone;
  5. copy that exact original to a collision-free backup name (`.bak-<stamp>`,
     `.bak-<stamp>-1`, … — 1000 names max), then
  6. `renameSync(temp, target)`.
- Every failure before the rename closes and unlinks only this process's temp
  file and leaves the original byte-identical; nothing here claims a rollback for
  a failure after the rename (there is none in the function).
- `writeRouteSettings`, `repairDefaultModelSettings` and `generateRoute` take an
  injectable `io` (node:fs-shaped) so failures and a competing editor are driven
  deterministically with no sleeps, no real profile and no subprocess.
- The no-op path returns before any temp, backup or rename.
- The `node:fs` import became `import * as fs` so the seam can default to it.

## Residual risk

- The pre-rename re-read is a best-effort compare-and-swap, not a lock: a
  non-cooperating editor can still save in the window between it and the rename.
  Documented in the function and in the README rather than described as a
  guarantee.
- Ownership is not preserved across the rename (impossible without privileges):
  the replacement is created by the process's own user. A settings file written
  by one user and group-writable by another would change owner; the plugin
  normally runs as the profile's owner.
- The parent directory is not fsynced (macOS answers EINVAL for a directory
  descriptor); what is promised is that complete bytes are renamed over the
  original, not that the rename itself survives a power loss.
- `tools/dsh_route.sh --write` still writes in place (see the new finding in the
  task report); it is the checkout tool, not this plugin's writer, and has no
  test seam for a rename failure.
