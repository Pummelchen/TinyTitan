# AUD-0045 — validate the route token count and port without coercion

Commit: (see `git log --grep 'audit(0045)'`)
Baseline: `06f6219f` (DSH 0.2.3-alpha.2; AUD-0032–0034 already cherry-picked).

## Root cause

Two more config fields still read their value through `Number(...)`:

- `resolveRouteTokenCount` (`context`, `maxTokens`) — `const tokens = Number(value)`
  then `Number.isSafeInteger(tokens) && tokens > 0`;
- the `port` block in `resolveConfig` — `Number(config.port ?? env ?? 8080)` then
  `Number.isInteger(port)` in 1..65535.

Measured on the baseline (`plugins/dsh-tinytitan/src/config.js`):

```
port true        -> accepted 1
port [8096]      -> accepted 8096
port "1e3"       -> accepted 1000
port " 8096"     -> accepted 8096
context true     -> accepted 1
context [65536]  -> accepted 65536
context "1e5"    -> accepted 100000
maxTokens [8192] -> accepted 8192
```

A malformed profile therefore silently declared a one-token window, a 65,536-token
window, or a route pointed at port 1 — all well-formed values to every later
consumer.

## Fix (`plugins/dsh-tinytitan/src/config.js`)

- One shared `wholeNumber(value)`: a `number` is returned as-is (the field's own
  bound still applies), canonical decimal text (`DECIMAL_INTEGER`,
  `^(?:0|[1-9][0-9]*)$`) is parsed, everything else answers `NaN` so the caller's
  existing range check refuses it. `resolveDebounce` and
  `resolveCompactionHeadroom` now read through it too — same rules, one source.
- `resolveRouteTokenCount`: accepts a safe whole number `> 0`, or canonical
  decimal text naming one. **`""` stays the documented "not set" sentinel** — an
  empty `TINYTITAN_CONTEXT`/`TINYTITAN_MAX_TOKENS` is how a shell clears the
  override, and the module's own contract says empty strings mean not set — while
  whitespace-only (`" "`), booleans, arrays, objects, exponent/hex/padded text,
  `0`, negatives, fractions, `NaN`, infinities and unsafe integers are refused
  with the existing field-named message.
- Port: the raw value (config, else `TINYTITAN_PORT`, else 8080) goes through
  `wholeNumber`, then the unchanged 1..65535 bound with `Number.isSafeInteger`.
  The refusal now names `rawPort`, so `TINYTITAN_PORT=eighty` reports
  `got eighty` instead of the old `got undefined` (the message used to print
  `config.port`, which is unset on the environment path).

No range, default or valid form changed: port 1 and 65535 still work, `context: 1`
and `context: Number.MAX_SAFE_INTEGER` still work, `"65536"`/`"9123"` still work,
and unset/`null`/`""` still mean "the writer's own pin".

## Tests (2 new; both RED before the fix) — `test/route.test.js`

The config tests live in `route.test.js` on this baseline (there is no
`config.test.js`).

- `the route token counts come only from real numbers or decimal text` —
  unset/`""` → `null`, `131072`/`8192`, `"65536"`/`"16384"`,
  `MAX_SAFE_INTEGER` accepted; for **both** `context` and `maxTokens` refuses
  `true`, `false`, `[]`, `[65536]`, `{}`, `" "`, `" 65536"`, `"65536 "`,
  `"0x10000"`, `"1e5"`, `"08"`, `0`, `-1`, `1.5`, `NaN`, `Infinity`,
  `MAX_SAFE_INTEGER + 1`.
- `the port is a real number in range, never a coerced one` — `8080` default,
  `1`, `8096`, `"9123"`, `65535` accepted; refuses `true`, `false`, `[]`,
  `[8096]`, `{}`, `""`, `" "`, `" 8096"`, `"8096 "`, `"1e3"`, `"0x1f90"`,
  `"8096a"`, `0`, `-1`, `1.5`, `65536`, `NaN`, `Infinity`,
  `MAX_SAFE_INTEGER + 1`; and `TINYTITAN_PORT=eighty` is refused with
  `got eighty`.

RED measured: `node --test test/route.test.js` → `tests 20, pass 18, fail 2`,
first failures `Missing expected exception: context true` and
`Missing expected exception: port true`.

## Residual risk

- **New finding, same class, not fixed here:** five resolvers still read through
  `Number(value)` and accept booleans/arrays — measured
  `autoGoalRounds: true → 1`, `autoGoalRounds: [5] → 5`,
  `autonomyRounds: true → 1`, `handoffHops: [3] → 3`,
  `handoffAtTokens: [50000] → 50000`, `handoffMaxChildren: true → 1`:
  `src/config.js:262` (`resolveAutoGoalRounds`), `:279`
  (`resolveAutonomyRounds`), `:295` (`resolveHandoffHops`), `:315`
  (`resolveHandoffAtTokens`), `:358` (`resolveHandoffMaxChildren`). Each is a
  one-line change to `wholeNumber` when the manager files them.
- The canonical-decimal grammar still rejects `"08"`, `"1e3"`, `" 65536"` and a
  padded string on purpose; a YAML number `8096` and the env form `"8096"` both
  work.
- `port: ""` is refused (as it was before, via `0` out of range) rather than
  treated as unset: a port has no "unset via empty string" contract, and the
  fallback order is `config`, `TINYTITAN_PORT`, `8080`.
