# Task 0021 — Prove allocation products and BLAS narrowing safe at the Swift–C boundary

**Status:** DONE (remediation committed on the audit branch)
**Base commit:** `53032da0f4622456cc606f048dc84fc729a5f176` (detached HEAD,

**Host:** macOS 27.2.1 (26B131), Apple M3, 24 GiB, Xcode 27.2 (27B52),

**Task classification:** investigation candidate, now a confirmed *latent*

past the fallback buffer.

## 1. Reachability — what was traced

- Declaration and contract: `sources/TinyTitanKernelsC/include/tinytitan_kernels.h:130`
  (before the change), definition `sources/TinyTitanKernelsC/gdn_chunk.c:72-126`.
- Swift callers, seven identical copies:
  `sources/TinyTitan/CPUEngine/CPUQwen35+BatchGDN.swift:213,236` and
  `sources/Engines/Qwen35Dense{2B,4B,9B}{4,8}Bit/CPUEngine/CPUQwen35+BatchGDN.swift`
  at the same lines. All go through `gdnApplyChunk`.
- Geometry: `gatedDeltaNetBatch` (`CPUQwen35+BatchGDN.swift:25-101`) passes
  `tokens = count <= TINYTITAN_GDN_CHUNK` (clamped to `1...128` at
  `CPUQwen35+BatchGDN.swift:20-23`), `dk = configuration.linearKeyHeadDim` and
  `dv = configuration.linearValueHeadDim`, and before the call it proves
  `convDim == 2 * hk * dk + hv * dv` and `z.count == tokens * valueWidth`
  (lines 53-60). `state` is `hv * dv * dk`, `readout` is `tokens * valueWidth`.
  The manifest values come from `AffineSnapshot+Loading.swift:48-49`; every
  in-tree Qwen 3.5 fixture uses 128 (`tests/TinyTitanRepack/...`, e.g.
  `QwenRepackPlannerTests.swift:471`).
- Consequence: with a real install, `dk`/`dv` are bounded by buffers that were
  actually allocated and `tokens <= 128`, so a `size_t` product cannot wrap and
  no `(int)` cast can truncate. The runtime crash path was therefore **not
  reachable** through a supported model.
- What *was* reachable and wrong:
  1. the C symbol is exported from `TinyTitanKernelsC` and its header stated no
     geometry precondition, so any in-package C/Swift caller could pass
     unbounded dimensions;
  2. the return code `1` meant both "allocation failed, fallback produced a
     valid result" and "allocation failed, nothing was written (dv > 256)";
     the Swift callers discarded the return value with `_ =`, so that second
     case left the readout zero-filled and generation silently wrong. Every
     shipped dense geometry uses `dv = 128`, so this needs an allocation
     failure with a geometry past the fixed buffer — a contract case, not a
     supported-install observation.

**Pre-fix proof (subprocess, tiny buffers).** A standalone harness with
`tokens=2, dk=1<<62, dv=1` (so `twoTokens*dk*4` and `dv*dk*4` wrap and
`(int)dk == 0`) compiled against `git show HEAD:sources/TinyTitanKernelsC/...`
with ASan+UBSan:

```
gdn_chunk.c:112:28: runtime error: subtraction of unsigned offset ... overflowed
gdn_chunk.c:111:28: runtime error: subtraction of unsigned offset ... overflowed
lda must be >= MAX(K,1): lda=0 K=0. ... BLAS error: Parameter number 9 ...
run exit=255
```

That is the unchecked arithmetic the task named. Running the same harness
against the fixed sources returns `returned 2 state=0.000000 readout=0.000000`
(exit 0) under the same sanitizers: rejected before any allocation or write.

## 2. Change

`sources/TinyTitanKernelsC/gdn_chunk.c`

- Strict C99 checked `size_t` helpers: `tinytitan_checked_add_size`,
  `tinytitan_checked_mul_size`, `tinytitan_scratch_bytes` (element product and
  byte product both checked; `SIZE_MAX` guards, no extensions).
- Validation order, all before the first allocation:
  1. zero `tokens`/`dk`/`dv` remains a documented no-op (`..._OK`);
  2. every stride is at least the width it indexes and alpha/beta strides are
     non-zero;
  3. all seven scratch products are computed and checked;
  4. `tokens <= INT_MAX/2`, `dk <= INT_MAX`, `dv <= INT_MAX` before any
     `(int)` cast (the `twoTokens` shared extent included).
- Return codes are now distinct:
  `0 OK`, `1 FELL_BACK` (fallback produced a valid result), `2 INVALID_GEOMETRY`
  (nothing allocated or written), `3 ALLOCATION_FAILED` (nothing written).
  `sources/TinyTitanKernelsC/include/tinytitan_kernels.h` documents all four.
- `tinytitan_delta_rule_chunk_with_allocator` (header
  `include/tinytitan_testing.h`) is the fault-injection seam: the production
  entry point passes `malloc`; the body is shared, so tests exercise the real
  paths.
- Valid geometry keeps every arithmetic expression and BLAS call unchanged;
  only the guards are new. `chunkedDeltaRuleMatchesTheTokenKernel` (existing)
  and the new scalar-reference test pin the numerics.

Swift callers (`CPUQwen35+BatchGDN.swift`, seven identical copies) now `try`
`gdnApplyChunk`, aggregate the per-head status (`Mutex<Int32>` on the parallel
branch), treat `0` and `1` as success, throw on `2`/`3` with `ModelError`
instead of returning a zero-filled readout. No `@unchecked Sendable`, no force
unwrap, no broad catch.

## 5. Self-audit

- Every allocation is sized from a checked product; every pointer offset in the
  kernel is bounded by one of those products and the validated strides.
- Free paths: all seven scratch pointers are freed exactly once on the
  allocation-failure branch and once on the success branch; no double free.
- A rejected geometry returns before any write, proved by sentinel buffers in
  five tests. The rejected call also returns before `malloc`.
- The fallback only runs when `dv <= TINYTITAN_CHUNK_FALLBACK_DV`; the return
  code now tells the caller whether output exists.
- No compiler extension, no suppression, no language-standard or flag change.
- Numerical identity: no expression changed; the existing chunk-vs-token test
  and the new 5×3×2 scalar comparison pass. A golden run was **not** possible —
  `models/` has no Qwen 3.5 dense install (only Inkling raw folders), and this
  task may not fetch one.

## 6. Residual risk and new findings

- **Residual:** the C entry point still cannot know the caller's buffer sizes,
  so a correct stride/width pair pointing at an undersized buffer is still the
  caller's contract. The header now states the destination sizes.
- **Residual:** `dv > 256` plus OOM is a hard failure (code 3) for a raw C
  caller that ignores the return; the Swift callers now throw.
- **New finding (not fixed, outside this task):**
  `sources/TinyTitan/Infrastructure/Streaming/ParallelExpertReader.swift:164`
  converts `Int` byte counts with `UInt32($0)`, which traps for a value above
  `UInt32.max`. Reachable only from an in-package caller that already passed a
  size the destination cannot hold; recorded for a future input-validation
  pass. No memory-safety consequence.
- No ledger or manual file was edited by this task.
