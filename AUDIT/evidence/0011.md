# Audit 0011 — actor reentrancy clears unsynced append accounting

**Host / base:** as 0010. Base commit for this task: `f6b8176c`.

## Root cause (confirmed)

`performBarrier` captured the descriptor, awaited the blocking queue, and then set
`pendingSinceSync = 0` when the descriptor number was unchanged. The actor is reentrant
at that await: an `append` admitted while the drive works writes a record the barrier
was never asked to cover, and the reset marked it durable. A run that then stopped had
no pending record left to force another flush, so the record existed only in the page
cache. Descriptor identity was the number, which `compact` can reuse for the new inode.

## Fix

`sources/ContinuityCore/Persistence/Journal.swift`:

- `appendedRecords` / `durableRecords` (`UInt64`, monotonic per descriptor generation).
  `pendingRecords` is the difference (saturating at `Int.max` for the getter).
- `performBarrier` captures the watermark **and** `descriptorGeneration` before
  dispatching. A completed barrier advances `durableRecords` only to the captured
  watermark, so a record appended during the await stays pending even if the drive
  happened to flush it. A descriptor swap (generation change) discards the result.
- `compact`/`truncate`/`shutDown` advance the generation; `compact` resets the
  watermark for the new file (the checkpoint itself is durable when it lands).

## Failing-before / passing-after

New suite `tests/ContinuityCore/JournalBarrierAccountingTests.swift`, 4 tests. The
barrier is held inside the syscall by a semaphore the injected filesystem signals
(`holdFullSync`), so the interleaving is the one under test, not one a sleep produced.

Failing-before run (temporarily restoring `durableRecords = appendedRecords` and the
descriptor-number identity):

```
swift test --no-parallel --filter JournalBarrierAccountingTests
  aRecordWrittenDuringABarrierIsNotCoveredByIt ... failed (pendingRecords == 0, wanted 1)
  aBatchAdvancesTheWatermarkByItsRecordCount ..... failed (pendingRecords == 0, wanted 1)
  Test run with 4 tests in 1 suite failed after 0.054 seconds with 2 issues.   EXIT:1
```

After the fix: `Test run with 4 tests in 1 suite passed after 0.029 seconds.` EXIT 0.
`swift test --no-parallel --filter Journal` after: 45 tests in 7 suites passed, EXIT 0
(the four tests the task names — `theBarrierLandsOnceAppendsStop`,
`aBusyWriterCannotPostponeDurabilityForever`, `explicitSyncIsImmediate`,
`compactionWaitsForAnInFlightBarrier` — are unmodified and pass).

## Residual risk

- The counters are `UInt64` and wrap deliberately with `&+=`; the difference is correct
  for any run with fewer than 2^63 records pending, which is every journal this type
  can hold.
- A barrier whose descriptor was swapped is discarded, not retried. The compaction
  that swapped it reset the watermark for the new file, so there is nothing to retry.
