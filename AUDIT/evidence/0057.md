# Audit 0057 — duplicate workspace header

## Finding: confirmed

`WorkspaceHeader.value(in:)` used `headers.first(name:)`, so two
`X-TinyTitan-Workspace` headers silently chose the first by wire order. The
workspace selects which project's persistent memory a request reads and writes;
order-dependent selection is the cross-project mixing the header exists to
prevent.

Reproduced with a raw-socket request before the fix: two distinct workspace
headers on `/v1/chat/completions` were routed (200), the backend was invoked, and
the request's workspace was the first value. The new test failed with three
expectations (`400`, `duplicate_workspace`, zero generations).

## Change

- `sources/TinyTitanServer/Core/HTTPServer.swift`: `WorkspaceHeader.resolve(in:)`
  returns `.absent`, `.named(String)` or `.duplicate`; `value(in:)` stays as a
  compatibility spelling for callers that only want the value.
- `HTTPServerHandler+Routes.swift`: admission refuses `.duplicate` with 400
  `duplicate_workspace` before routing. The repeated "HEAD has no body" branch
  became `writeAdmissionRefusal`, now shared with the Host/Origin policy.
- Single headers are unchanged: trimming and the empty-header rule are the same.

## Tests

- `duplicateWorkspaceHeaderIsRefused` (raw socket): two values -> 400
  `duplicate_workspace`, zero generations.
- Existing `theWorkspaceHeaderReachesTheBackend` still passes (single value
  reaches the backend).
- Existing `OpenAIValidationTests.workspaceHeaderIsReadAndTrimmed` still passes
  through the retained `value(in:)`.

Focused run: `swift test --no-parallel --filter
"duplicateWorkspaceHeaderIsRefused|theWorkspaceHeaderReachesTheBackend|LoopbackTrustTests"`
-> 15 tests in 2 suites passed.

## Residual

Duplicates of other non-routing headers are still first-wins unless they have
their own policy; this task covers the workspace contract only. The race where a
proxy appends a duplicate for a header the server does not validate remains a
proxy misconfiguration, not an accepted request.
