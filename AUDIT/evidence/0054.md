# AUD-0054 — checked loop arithmetic in the Inkling 2 architecture

Commit: `audit(0054): …` (see `git log --grep 'audit(0054)'`)

Baseline: detached `ecab30e7` (after AUD-0053).

## Defect proved before the fix

Two unchecked products came from untrusted metadata:

```swift
// Inkling2GGUFArch.archInfo
let stored = unrolled - (passes - 1) * (loopEnd - loopStart)

// Inkling2GGUFArch.slidingLayers
let visit = layer < loopEnd ? layer : layer + (passes - 1) * (loopEnd - loopStart)

// Inkling2Arch.Parameters.unrolledLayers, used by the shared archInfo
var unrolledLayers: Int { storedLayers + (loopPasses - 1) * (loopEnd - loopStart) }
```

`passes`, `block_count` and the core bounds are metadata. A `num_loops` of
2^62 over a four-layer core makes `(passes - 1) * 4` exceed `Int`; the old
`*` traps. `storedLayers = Int.max` makes the shared `unrolledLayers` sum trap.

## Fix

`sources/TinyTitanRepack/Core/Format/Inkling2Arch.swift`

- `checkedAdd`/`checkedSubtract`/`checkedMultiply` (Int) throw
  `RepackError.configurationInvalid` on overflow.
- `extraLoopLayers(loopStart:loopEnd:passes:field:)` computes
  `(passes - 1) * (loopEnd - loopStart)` with every step checked.
- `storedLayers(unrolled:loopStart:loopEnd:passes:field:)` subtracts the extra
  visits from the unrolled count with checked arithmetic.
- `archInfo` validates the semantic loop guard first, then computes the extra
  visits and the unrolled total checked, and uses that local value for the
  `unrolledLayers` manifest scalar. The unchecked `Parameters.unrolledLayers`
  property is removed (its only caller was this function).

`sources/TinyTitanRepack/Core/Format/Inkling2GGUFArch.swift`

- `archInfo` uses the semantic guard, then `Inkling2Arch.storedLayers`, then the
  existing `stored > 0, loopEnd <= stored` check.
- `slidingLayers` is split into a header wrapper and a pattern-based function:
  the wrapper only fetches the pattern, and the pattern function computes the
  extra visits with `extraLoopLayers` and each `layer + extra` with
  `checkedAdd`. The pattern function is directly testable.

Valid plans are unchanged: the fixture still reads two layers, and the shared
`archInfo` still writes `unrolledLayers: 4` for the two-layer/two-pass fixture.

## Tests added

`tests/TinyTitanRepack/Core/Format/Inkling2GGUFArchTests.swift`:

- `num_loops = 2^62`, `core_end = 4`, `block_count = 4` → `RepackError`;
- `storedLayers = Int.max`, `loopEnd = 1`, `passes = 2` → `RepackError`;
- `extraLoopLayers` normal and overflowing; `storedLayers` normal and
  underflowing; `checkedAdd`/`checkedSubtract`/`checkedMultiply` at the limits;
- sliding-window mapping over a six-entry pattern (visits 0,1,4,5 → `[1,2]`)
  and a `passes = Int.max` case where `layer + extra` overflows → `RepackError`;
- a valid parameter set still yields `numLayers == 2` and `unrolledLayers == 4`.

## Residual risk

- The helpers are raw checked arithmetic: `extraLoopLayers(loopStart: 3,
  loopEnd: 2, …)` returns a negative count by design; every caller validates the
  loop's semantics first (`loopEnd > loopStart`, `passes >= 1`). That ordering
  is pinned by the fixture tests.
- `unrolledLayers` is now computed in `archInfo`; any future caller that needs
  it must use the checked route rather than re-deriving the product.
