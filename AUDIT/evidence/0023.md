# AUD-0023 — safe YAML scalars for the catalog and configuration fields

Commit: (see `git log --grep 'audit(0023)'`)

## Root cause

Both route writers interpolated catalog-sourced strings and operator config into
YAML unquoted:

- `plugins/dsh-tinytitan/src/generate.js` — `buildBlock` wrote `provider`,
  `reasoning`, `- id:`, `name:` and the `reasoningEfforts` keys/values with
  `${...}`; `textField` only rejected empty/multi-line, and the numeric fields
  were `String()`ed.
- `tools/dsh_route.sh` — the same seven sites, built with `block+="..."`.
- `plugins/dsh-tinytitan/src/config.js` — `provider`/`reasoning` were checked for
  non-empty only, so `reasoning: "loud"` reached the writer (the shell tool
  exits 2 on that value).

Measured on the pre-fix writer: a catalog name of `Evil: name # not a comment`
produced `bad indentation of a mapping entry` from js-yaml at the provider line
(after `evil: provider # x:`), and names `null`/`true` parsed as null/boolean.

## Fix

- `yamlScalar()` in `generate.js`: a value is emitted bare only when it matches a
  conservative plain-scalar grammar (`^[A-Za-z_][A-Za-z0-9 _.,()+/@-]*$`), has no
  trailing space and is not `true/True/TRUE/false/False/FALSE/null/Null/NULL`;
  otherwise it is a double-quoted scalar with `\`, `"` and C0/DEL escaped.
- `yaml_scalar()` in `tools/dsh_route.sh` implements the identical rule byte for
  byte (byte-wise under `LC_ALL=C`, so UTF-8 passes through and the result does
  not depend on the developer's locale).
- The three numeric lines go through `integerField` (safe integer, canonical
  decimal string accepted, port 1..65535, tokens >= 1).
- A model id is now held to `[A-Za-z0-9][A-Za-z0-9._-]*` in both writers (the
  shell's `--from-server` path and the plugin's `servedIdsInLines` reader already
  require one `\S+` token); a free-form display name is quoted instead of
  stripped.
- `resolveConfig` validates `reasoning` against `REASONING_LEVELS`
  (`off|minimal|low|medium|high|xhigh|max`), the same set the shell tool accepts.
- Level values are split on `,` before serialization, mirroring the shell's
  join/split transport, so a comma inside a level cannot desynchronise the two
  writers.

## Residual risk

- A plain scalar is validated against YAML 1.2's core schema. `on`/`off`/`yes`/
  `no` are deliberately left bare because the generated effort ladder already
  emits `off:` as a key and the harness reads 1.2; a YAML 1.1 parser would read
  those four as booleans in any route this project has ever written.
- The catalog is JSON from the server or a folder scan; an operator hand-editing
  a catalog can still name a model with an arbitrary display name, which is now
  quoted, and cannot inject structure.
- Root keys inside a quoted scalar are impossible, but the value of `name` for a
  model whose id does not end in `_N-Bit` gets no width suffix (pre-existing).
