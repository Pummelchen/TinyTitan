# Audit 0035 — the catalog tested the tokenizer closure, not a call

## Finding: confirmed, with a failing-before test

`ModelCatalog.probePluginInstall` accepted an install when

    GFTokenizer.tokenizerFolder(forModelDirectory:) != nil
        || factory.tokenizerFolder != nil

The second term only proves the plugin *declares* a hook. A Q4 plugin install
has no `tokenizer/` folder by design: its tokenizer is exported from the GGUF
header (`inkling2_gguf_header.bin`). With that header missing, the install was
still catalogued and failed on first use.

Reproduced with a synthetic plugin (a registry plugin whose tokenizer source is
`tokenizer-source.bin`) and a manifest-only install, against the parent code:

    aPluginInstallWithoutItsTokenizerSourceIsNotCatalogued
    -> Expectation failed: catalog.entries.isEmpty
    -> Expectation failed: catalog.skipped.first.reason
    (2 issues; the install was catalogued)
    aPluginInstallWithItsTokenizerSourceIsCatalogued -> passed

## Change

- `sources/TinyTitanCore/Engine/EngineFactory.swift`: new optional
  `tokenizerSourceIsPresent: (@Sendable (URL) -> Bool)?`, documented as the
  cheap precondition a host may check instead of running the hook. It must be a
  local file/manifest fact, never a parse or a write.
- `sources/Engines/Inkling2GGUFQ4/Plugin/Inkling2GGUFQ4Plugin.swift`: supplies
  the predicate — the install's GGUF header exists. The hook itself (which
  exports the tokenizer sidecar) is unchanged and still runs at load.
- `sources/TinyTitanServer/Core/ModelCatalog+Plugins.swift`:
  - predicate present: call it; false -> skip with "plugin tokenizer source is
    missing; the install is incomplete";
  - no predicate but a hook: call the hook (bounded by the plugin) and skip on
    throw, instead of trusting the closure's presence;
  - no hook: the generic `GFTokenizer.tokenizerFolder` rule, unchanged.
- `plugins/dsh-tinytitan/src/catalog-scan.js`: the Q4 variant now carries
  `tokenizerSource: "inkling2_gguf_header.bin"` and the scan requires that file
  to exist; the NVFP4 variant keeps the `tokenizer/tokenizer.json` check. This is
  the same source predicate as the Swift side.

No model, no GGUF parsing and no network in the catalog probe.

## Residual

- The predicate proves the header file exists, not that it is a valid GGUF. A
  corrupt header still passes the catalog and fails when the tokenizer is
  exported at load; a full parse in the catalog would be large I/O, which the
  task rules out.
- A plugin with a hook and no predicate is validated by calling the hook once
  during the scan; that call is bounded by the plugin (the shipped Q4 plugin now
  supplies the predicate instead).
- The JS mirror and the Swift catalog agree by the same rule; the end-to-end
  parity test was skipped on this machine because no release binary/models
  directory exists.
