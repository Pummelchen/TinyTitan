# AUD-0032 — make `tools/dsh_route.sh --write` replace the settings file atomically

Commit: (see `git log --grep 'audit(0032)'`)

## Root cause

The `--write` branch copied the settings file to `.bak-$(date …)` and then handed
the target to a Python heredoc that called `path.write_text("".join(out))` — a
truncate-and-write in place. A crash, a full disk or a failing write left a
partial profile; an editor's save between the read and the write was overwritten
with text computed from the stale file; a run that changed nothing still rewrote
the file and piled up another `.bak-<second>`; and a backup name already taken in
the same second was overwritten by `cp`. The plugin's own writer
(`plugins/dsh-tinytitan/src/generate.js`) had been fixed under AUD-0024; this
checkout tool had the same defect and no test of either failure shape.

## Fix

The whole replacement now lives in the same Python heredoc (no new dependency; the
script already requires `python3`):

1. read the file once (`utf-8`, universal newlines) and compute the new text;
2. **no-op** when the text is unchanged: print `already current`, write nothing,
   make no backup;
3. resolve symlinks (`os.path.realpath`), so a `settings.yaml` kept in a dotfiles
   checkout stays a link and its target is replaced;
4. `tempfile.mkstemp` beside the target (same directory, so the rename is a
   rename), write, `flush`, `os.fchmod` the original mode, `os.fsync`, close;
5. re-read the target and compare it with the exact text the replacement was
   computed from; a difference exits with
   `… changed while the route was being written; nothing was replaced` and the
   original is untouched (no backup is made for a refused write);
6. copy that exact original to a collision-free backup name (`.bak-<stamp>`,
   `.bak-<stamp>-1`, … — 1000 names max);
7. `os.replace(temp, target)` — one rename;
8. every failure before the rename removes only this run's temporary file; a
   non-zero exit is 1 and the original is byte-identical. The summary lines moved
   into the same Python block, because bash 3.2 cannot even *parse* a quoted
   here-document holding an apostrophe inside `$( )` (measured; the
   `shell-portability` gate catches it), so the status goes to stdout — where the
   plugin reads it — and the operator's lines to stderr.

Two test seams, both inert unless set and both **fail-closed** (they can only
make the replacement refuse, never let a write through):

- `TINYTITAN_SETTINGS_STAMP` pins the backup's timestamp suffix (the collision
  test needs a predictable name; the default is the UTC second, as before);
- `TINYTITAN_SETTINGS_TEST_FAULT=conflict` makes the re-read look like another
  editor's save, and `=replace` fails between the complete temporary file and its
  rename — the two windows the old writer could not survive.

Byte parity of `--print` is untouched; the block is built exactly as before.

before the fix):

| `a symlinked settings file stays a symlink` | guard |

## Residual risk

- The pre-rename re-read is a best-effort compare-and-swap, not a lock: a
  non-cooperating editor can still save in the window between it and the rename.
  Documented in the script rather than claimed as a guarantee.
- The parent directory is not fsynced (macOS answers EINVAL for a directory
  descriptor). What is promised is that complete, fsynced bytes are renamed over
  the original — not that the rename itself survives a power loss.
- Ownership is not preserved across the rename; the replacement is created by the
  process's own user, as with the plugin writer.
- The two `TINYTITAN_SETTINGS_*` seams are environment variables. They are
  documented in the script header, cannot enable a write, and are not read
  anywhere else; if that is judged too much surface, they can be replaced by a
  unit test of the heredoc once the block is factored into a standalone
  `tools/dsh_route_settings.py`.
