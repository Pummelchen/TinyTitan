# Task 0037 — CI compiles the library demo

Status: DONE. The new `library-demo` job is in `.github/workflows/ci.yml`.

## Why

`examples/library-demo` is a shipped release artifact, but its build scripts do not
read a SwiftPM manifest: the strict standard (`-swift-version 6
-strict-concurrency=complete -warnings-as-errors`, added by 0005) lives only in
those scripts. Before this job, no CI step compiled the demo, so a regression
there was invisible until a user built it. `tools/release.sh` only asserted the
scripts were present in the archive.

## Job

`library-demo` (`runs-on: xcode-27`, same trigger guard as `test`) checks out the
tree, then:

```
scratch="$RUNNER_TEMP/library-demo-build"
dist="$RUNNER_TEMP/library-demo-dist"
tools/build_library.sh 0.0.0-ci --out "$dist" --scratch-path "$scratch"
examples/library-demo/build-static.sh "$dist"
examples/library-demo/build-dynamic.sh "$dist"
# every demo binary must be exactly arm64
# the dynamic one must link @rpath/libTinyTitanLib.dylib
```

The scratch and dist directories are deliberately separate: `build_library.sh`
runs `rm -rf "$OUT"` before staging, so a build directory under `--out` is deleted
with the products still inside. That was measured locally on the first run of the
job's exact commands (the script reported "no .a archives ... the static build did
not run" against the deleted tree).

## Verification (local, 2026-11-26, macOS 27.2 / Xcode 27.2 / Swift 6.4.2)

The job's exact commands, with separate `--out` and `--scratch-path`, ran from
this checkout:

- `tools/build_library.sh 0.0.0-ci --out … --scratch-path …`: **exit 0**; staged
  `libTinyTitanLib.a` (50,198,608 bytes), `libTinyTitanLib.dylib` (34,549,928),
  the module set, C module maps, the Metal resource bundle and the demo sources.
- `build-static.sh` / `build-dynamic.sh`: **exit 0**, both print `built …`.
- `lipo -archs`: **arm64** on both demos.
- `otool -l … | grep LC_RPATH`: `@executable_path/lib`; `otool -L`:
  `@rpath/libTinyTitanLib.dylib`.
- `--help`: exit 0 for both binaries (the dynamic one proves the rpath resolves).
- YAML parses (`jobs: [test, library-demo, thread-sanitizer, supply-chain]`), and
  the `run:` block passes `bash -n`.

The job needs no model, no network beyond the normal checkout and no publish. It
does not run generation (the demo needs an install for that), only the compile
and link that this finding is about.
