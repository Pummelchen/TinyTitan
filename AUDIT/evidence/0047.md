# Audit 0047 — journal JSON encoding is not byte-stable within a process

**Host / base:** macOS 27.2.1 arm64, 24 GB, Xcode 27.2 / Swift 6.4.2. Detached HEAD
`40d16cda` (audit branch), worktree `.agent-worktrees/journal`.

## Root cause (reproduced)

`FileJournal`'s `JSONEncoder` set only `.withoutEscapingSlashes`
(`Journal.swift:123`). Foundation's `JSONEncoder` does not promise object key order and
in practice varies it between two encodes of the same value in one process. Reproduced
on the original behaviour: eight appends of one `ContinuityTask` produced more than one
distinct byte string, and the line's first key was not any fixed field. A journal is
compared byte for byte in recovery tests and operator inspection, so an encode-order
change is indistinguishable from damage.

## Fix

`Journal.swift`: encoder/decoder construction is centralised in `makeEncoder()` /
`makeDecoder()`, and the encoder's output format is documented as
`[.withoutEscapingSlashes, .sortedKeys]`. Every write path (single append, batch,
checkpoint) uses the same instance built by `makeEncoder`; every read path (`replay`,
`readDetailed`) uses `makeDecoder`. No schema change: JSON objects are unordered, so
records written before this fix decode exactly as before (covered below).

## Failing-before / passing-after

New suite `tests/ContinuityCore/JournalEncodingTests.swift`:

- `theSameRecordEncodesToTheSameBytesEveryTime` — 8 appends of one record, all lines
  must be identical.
- `everyObjectInALineHasItsKeysSorted` — the line starts `{"task":{"_0":{"createdAt":"`
  and the five task keys appear in lexicographic order.
- `aRecordWithUnsortedKeysStillDecodes` — a fixture written with the pre-fix encoder
  (ISO8601, no sorted keys) still decodes, and a new append beside it is read back.

Failing-before run (`.sortedKeys` removed, everything else fixed):

After: 3/3 passed. `swift test --no-parallel --filter Journal`: 91 tests in 14 suites
passed, EXIT 0.

## Self-audit

- The encoder is the one used by `append`, the batch append and `compact` (all through
  `self.encoder`); `makeEncoder` is the only construction site in `sources/`.
- No golden or fixture was regenerated. The old-format fixture is generated by the
  test from a deliberately legacy encoder, so it cannot silently follow a future change.

## Residual risk

- `.sortedKeys` sorts by Unicode scalar order, so a future key whose order matters
  against another (e.g. a numeric suffix) sorts `"k10" < "k2"`. Keys are field names,
  not data, so this is cosmetic.
- Byte stability is promised for one process and build. It is not a cryptographic
  canonicalisation; a future Foundation change to *value* formatting (e.g. float
  spelling) would still move bytes, and no golden should assume otherwise without a
  decode-and-compare step.
