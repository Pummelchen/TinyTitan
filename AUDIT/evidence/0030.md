# Task 0030 — test-target concurrency warnings

Status: DONE. Fixed in this worktree; `swift build --build-tests` now emits 0 of the 12 diagnostics.

## Reproduction (before)

`swift build --build-tests` exited 0 while emitting 12 diagnostics from
`tests/TinyTitan/Kernels/MoE/GGUFReadScalingTests.swift`:

- capture of `read` with non-Sendable type `(GGUFTensorRange) -> ()` in a `@Sendable` closure
- reference/mutation of captured var `index` in concurrently-executing code
- reference to captured var `ranges` in concurrently-executing code
- concurrently-executed local function `read` must be marked `@Sendable`

The target *does* carry `-swift-version 6 -warnings-as-errors` (verified in the verbose
`swiftc` command for `-module-name TinyTitanTests`). A `#warning("audit 0030 probe")` in the same
file **fails** the build (`error: … audit 0030 probe`, exit 1), so the flag works for ordinary
warnings; these Swift-6 `SendableClosureCaptures` diagnostics are not promoted by it. The tree's
zero-warning standard was therefore not enforced for this class, and the diagnostics were real:

- one 1 MiB `MTLBuffer` was shared by every `concurrentPerform` worker and all of them `pread`
  into it concurrently — a data race on the destination bytes, not only a warning;
- `index` was a captured `var` guarded by `NSLock`, and `read`/`ranges` were captured non-Sendable
  values.

## Fix

`GGUFReadScalingTests` now:

- makes `ranges` a `let` (Sendable `GGUFTensorRange` values, built with `flatMap`);
- marks the local `read` function `@Sendable` and passes the destination buffer as a parameter,
  so it captures only the Sendable `url`;
- replaces the `NSLock`-guarded `var index` with `Synchronization.Mutex` (Sendable);
- allocates one 1 MiB `MTLBuffer` per worker inside the concurrent closure (capturing the
  already-`@unchecked Sendable` `MetalContext`), removing the shared-buffer race.

## Verification

- `swift build --build-tests`: **exit 0, 0** `SendableClosureCaptures`/concurrently-executed
  diagnostics (was 12).
- `swift test --no-parallel --filter GGUFReadScalingTests`: 1 test in 1 suite, skipped by its
  documented `.enabled(if: TINYTITAN_GGUF_MODEL)` gate (no raw GGUF install on this host); the
  suite compiles and is discovered.
- `tools/lint.sh swift-format`: clean (1835 files). SwiftLint in the main worktree is polluted by
  nested agent worktrees; the clean-worktree run is the gate (see baseline evidence).
- Negative control retained: a `#warning` in the same file fails the build (proved before the fix
  and re-proved by the flag being present in the compile command).

## Residual risk

The test remains gated on a raw GGUF install, so its *runtime* measurement was not executed here;
the compile-time defect and the data race are removed. No product code changed.
