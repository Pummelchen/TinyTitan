## 1. The defect, verified against the tree

At the base commit both scripts compiled the demo with no language standard at
all:

- `examples/library-demo/build-static.sh:46` — `swiftc -O \` followed by
  `-I "$DIST"`, `@"$DIST/swiftc-flags.txt"`, `-D STATIC_LINK`, `main.swift`,
  `libTinyTitanLib.a`, `-o`.
- `examples/library-demo/build-dynamic.sh:52` — the same, with `-D DYNAMIC_LINK`,
  `-L/-lTinyTitanLib` and the rpath linker flags.

No `-swift-version`, no `-strict-concurrency`, no `-warnings-as-errors`: these
builds never read the package manifest, so the root package's standard did not
reach them.

Measured consequence, not inferred — the **pre-change** scripts, restored from
`git show HEAD:examples/library-demo/build-*.sh` into a scratch directory, were
run against the same scratch distribution with a `#warning` appended to the
demo source:

| command | exit | output |
| --- | --- | --- |
| pre-change `build-static.sh` (demo with `#warning`) | **0** | `built …/tinytitan-demo-static` |
| pre-change `build-dynamic.sh` (demo with `#warning`) | **0** | `built …/tinytitan-demo-dynamic` |

A warning was invisible and a success line was printed. That is the defect.

## 2. Change

One added argument group on the single `swiftc` line of each script, and the
existing arguments kept in their original order:

```
swiftc -O -swift-version 6 -strict-concurrency=complete -warnings-as-errors \
```

- `build-static.sh:53`, `build-dynamic.sh:59` — the two lines are byte-identical
  (`diff` of the two `swiftc -O` lines: no output).
- `-D STATIC_LINK` / `-D DYNAMIC_LINK`, `-I "$DIST"`, `@"$DIST/swiftc-flags.txt"`,
  `-L/-lTinyTitanLib`, `-Xlinker -rpath -Xlinker @executable_path/lib`, the
  `main.swift` input, `-o "$OUT"`, `$OUT="$HERE/tinytitan-demo-…"`, the bundle
  copy loop, the `mkdir -p "$HERE/lib"`, the dylib copy and both `echo` lines are
  unchanged.
- `set -euo pipefail` is unchanged, and `swiftc` is a bare command in the script
  body, so a compiler failure aborts the script before the `echo "built …"` —
  proven in §4 rather than asserted.
- A comment above each invocation states the standard, why it is in the command
  line (these scripts never read the manifest), and that the line must stay
  identical across the two scripts.
- `README.md` gained one sentence in **Build** naming the flags, because the
  README is what ships next to the scripts in every library archive.

`-strict-concurrency=complete` **is** kept: the pinned compiler accepts it under
`-swift-version 6` (measured, exit 0, no diagnostic), so it is redundant rather
than rejected, and it keeps the intent legible. Swift 6 mode is what actually
enforces it (proof in §3.3).

### Resolved invocations (captured with `bash -x`)

```
swiftc -O -swift-version 6 -strict-concurrency=complete -warnings-as-errors \
  -I <dist> @<dist>/swiftc-flags.txt -D STATIC_LINK <demo>/main.swift \
  <dist>/libTinyTitanLib.a -o <demo>/tinytitan-demo-static

swiftc -O -swift-version 6 -strict-concurrency=complete -warnings-as-errors \
  -I <dist> @<dist>/swiftc-flags.txt -D DYNAMIC_LINK -L <dist> -lTinyTitanLib \
  -Xlinker -rpath -Xlinker @executable_path/lib <demo>/main.swift \
  -o <demo>/tinytitan-demo-dynamic
```

Warnings in either build log: **0**. The `@swiftc-flags.txt` file cannot override
the strictness: it contains 84 lines, all `-Xcc` / `-fmodule-map-file=…` pairs
(42 pairs); 0 lines name `-swift-version`, `-strict-concurrency`,
`-warnings-as-errors` or `-D`.

### 3.2 Non-Sendable crossing probe

```swift
final class AuditProbeBox {
    var value = 0
}

func auditProbeNonSendable(_ box: AuditProbeBox) async {
    Task { box.value += 1 }
}
```

| command | exit | `built` line | diagnostic |
| --- | --- | --- | --- |
| `build-static.sh <dist>` | **1** | absent | `main.swift:211:5: error: passing closure as a 'sending' parameter risks causing data races … [#RegionIsolation::SendingClosureRisksDataRace]` |
| `build-dynamic.sh <dist>` | **1** | absent | same |

### 3.3 The flags are what cause the failures (compiler-level, same pinned swiftc)

| probe | flags | exit |
| --- | --- | --- |
| `#warning` | `-swift-version 6 -strict-concurrency=complete -warnings-as-errors` | **1** (error) |
| `#warning` | `-swift-version 6 -strict-concurrency=complete` | **0** (plain warning) |
| non-Sendable Task crossing | `-swift-version 6 -strict-concurrency=complete` | **1** (error) |
| non-Sendable Task crossing | `-swift-version 5` | **0** |

So `-warnings-as-errors` is what makes a warning fatal, and the Swift 6 language
mode is what makes the data-race diagnostic an error at all — the two flags do
different jobs and both are needed.

## 7. New findings (reported, not fixed)

1. **No automated check compiles the demo.** `.github/workflows/ci.yml` has no
   job that runs `examples/library-demo/build-static.sh` or `build-dynamic.sh`;
   `tools/release.sh:520` only asserts that `demo/build-dynamic.sh` is *present*
   in the archive. A regression in these two scripts (a link-flag change, a
   dist-layout change, a language-standard change) reaches a release with no
   failing check — which is how the missing standard survived. Suggested fix (not
   applied): a CI step that runs `tools/build_library.sh` into a scratch dir and
   both demo scripts against it, as this evidence did by hand.
2. **`build-static.sh:65` / `build-dynamic.sh:74` `rm -rf "${HERE:?}/$(basename
   "$bundle")"`** deletes a directory under the demo dir before copying. It is
   guarded by `${HERE:?}` and restricted to `*.bundle` names, so it is not a
   defect today; noting it because the task asked for shell cleanup review and
   this is the only destructive operation in the pair.
