# AUD-0046 — validate the remaining numeric config fields without coercion

Commit: (see `git log --grep 'audit(0046)'`)
Baseline: `c4c26ee5` (DSH 0.2.3-alpha.2; AUD-0032–0034 and 0045 applied).

## Root cause

Five more config resolvers read their value through `Number(...)`, so a malformed
profile became a well-formed budget. Measured on the baseline
(`plugins/dsh-tinytitan/src/config.js`):

```
autoGoalRounds true        -> accepted 1
autoGoalRounds [5]         -> accepted 5
autonomyRounds true        -> accepted 1
handoffHops [3]            -> accepted 3
handoffAtTokens [50000]    -> accepted 50000
handoffMaxChildren true    -> accepted 1
handoffHops "1e2"          -> accepted 100
handoffAtTokens " 50000"   -> accepted 50000
```

Each value is a budget for unattended work — rounds, hops, the prompt-token
threshold that starts a handoff, and the process-wide child ceiling — so `true`
meaning “1 round” is exactly the kind of silent policy change the field exists to
make explicit.

## Fix (`plugins/dsh-tinytitan/src/config.js`)

Each resolver now reads through the shared `wholeNumber` introduced in AUD-0045
(a real number, or canonical decimal text `^(?:0|[1-9][0-9]*)$`; anything else
answers `NaN` so the field's own range check refuses it with its own message):

| resolver | line | accepted | default | sentinel |
| --- | --- | --- | --- | --- |
| `resolveAutoGoalRounds` | 265 | safe integer `> 0` or decimal text | `99999` | `""`/absent |
| `resolveAutonomyRounds` | 284 | safe integer `> 0` or decimal text | `64` | `""`/absent |
| `resolveHandoffHops` | 302 | safe integer `> 0` or decimal text | `3` | `""`/absent |
| `resolveHandoffAtTokens` | 324 | safe integer `> 0` or decimal text (`0` refused) | `null` (auto) | `""`/absent |
| `resolveHandoffMaxChildren` | 369 | safe integer `> 0` or decimal text | `8` | `""`/absent |

Ranges, defaults and the documented empty-string “not set” sentinel are
unchanged; each docstring now names the accepted forms and the refusal. Refused
with the existing field-named message: booleans, arrays, objects,
whitespace-only and padded strings, exponent/hex text, `0`, negatives, fractions,
`NaN`, infinities and integer-valued numbers past `Number.MAX_SAFE_INTEGER`.

## Residual risk

- The refusal interpolates `${value}`, so an array renders as its joined contents
  (`[5]` reads `got 5`). The field name and the refusal are correct; only the
  quoted value is lossy. Changing it would touch every message added in 0026,
  0033, 0045 and their regex assertions, so it is recorded rather than done.
- Canonical decimal text only: `"05"`, `"1e2"` and padded strings stay refused by
  design, while the YAML number and the plain string (`"30"`) both work.
- `resolveHandoffWindowRatio` is the one fraction field and keeps its own
  `DECIMAL_FRACTION` path (AUD-0033); `wholeNumber` is deliberately only for
  whole-number fields.
- No shell/route file was touched; `tools/dsh_route.sh` and
  `benchmark/test_dsh_route.py` are unchanged in this commit.
