# AUD-0043 — checked raw-total accounting in `--compress-experts`

Commit: `audit(0043): …` (see `git log --grep 'audit(0043)'`)

Baseline: detached `1cbc2c47` (after AUD-0042).

## Defect proved before the fix

`CompressExpertsTool.run` built the result summary with unchecked arithmetic:

```swift
rawBytes: input.rawLayerBytes * UInt64(input.layers.count),
compressedBytes: layerResults.reduce(0) { $0 + $1.result.compressedBytes },
indexBytes: layerResults.reduce(0) { $0 + $1.result.indexBytes },
```

`*` and `+` on `UInt64` trap at `UInt64.max`. The product was computed *after*
the copy and compression, so a plan whose declared layer total cannot fit would
trap after hours of work instead of refusing the plan.

**Red note.** A behavioural RED needs a real install whose declared raw size is
above 16 EiB: `loadInput` insists every layer file on disk is exactly
`expertsPerLayer * expertStride` bytes, so constructing the input would require
a sparse layer of that size and the copy would still try to read it. The
failing-before proof is therefore static (the expression above) and the boundary
is pinned on the new helper; the task explicitly allows that for a
non-constructible fixture, as AUD-0040 documents.

## Fix

`sources/TinyTitanRepack/Core/Workflow/CompressExpertsTool.swift`

- `totalRawBytes(rawLayerBytes:layerCount:)` multiplies with
  `multipliedReportingOverflow` and throws
  `RepackError.configurationInvalid` (negative layer count included). `run`
  calls it immediately after `loadInput`, before `copyPayload` or any
  compression, and uses the value for the result.
- `totalBytes(_:field:)` sums with `addingReportingOverflow` and throws the same
  typed error. `run` computes the compressed/index totals before writing the
  layout and receipt, so an (unreachable for real files) overflow is a failed
  conversion that removes the partial output, not a trap after success.

Both helpers are internal so the boundary is unit-testable without an install.

## Tests added

`tests/TinyTitanRepack/Core/Workflow/CompressExpertsToolTests.swift`:

- `1 << 40` × 4 layers = `1 << 42`;
- `UInt64.max / 2` × 2 = `UInt64.max - 1`;
- `UInt64.max / 2 + 1` × 2 throws; a negative layer count throws;
- sums `[1,2,3] = 6`, `[] = 0`, `[UInt64.max, 1]` throws.

`swift test --no-parallel --filter CompressExpertsToolTests`: **2 tests**, pass.
The existing end-to-end `compressedInstallLoadsAndStreamsEveryExpert` (Metal,
synthetic toy install) still passes, so the normal result values and written
bytes are unchanged.

## Residual risk

- The sums of per-layer compressed/index bytes are bounded by bytes actually
  written to disk, so their checked failure is unreachable in practice; the
  check is a guard, not a new rejection for any valid install.
- The raw total is still a *declared* product; a plan that fits `UInt64` but is
  larger than the disk fails at the existing disk-space check, not here.
